# Pixel Office LAN — 설계 문서

작성일: 2026-10-21 · 기반: [pixel-agents](https://github.com/pixel-agents-hq/pixel-agents) v1.5.0 (MIT) 포크

## 1. 의도와 이유

pixel-agents 는 **내 PC 의** AI 코딩 에이전트를 픽셀아트 사무실 캐릭터로 보여 준다. 우리는 이것을
**같은 망(LAN)의 동료들 에이전트까지 한 사무실에 모아** 보여 주고 싶다.
"누가(닉네임) · 어떤 에이전트(Claude/Codex)가 · 어느 방에서 · 뭘 하고 있는지"를 팀이 함께 본다.
설치 파일 하나로 누구나 쉽게 설치·실행할 수 있어야 한다.

## 2. 목표

1. **사무실 하나에 LAN 전원의 에이전트가 모인다.** 캐릭터 아래 이름표 `닉네임 · Claude #1` / `닉네임 · Codex #1`. Claude/Codex 는 이름표 아이콘·색으로도 구분.
2. **하는 일에 따라 방을 옮겨 다닌다** (원작에 없는 신규 기능 — 원작은 고정 좌석 + 애니메이션).

   | 방     | 상태                                                                |
   | ------ | ------------------------------------------------------------------- |
   | 코딩실 | 파일 수정 (Claude: Edit/Write/NotebookEdit · Codex: apply_patch 등) |
   | 자료실 | 검색·읽기·웹 (Read/Grep/Glob/WebSearch/WebFetch 등)                 |
   | 서버실 | 명령 실행 (Bash · Codex shell/exec)                                 |
   | 대기실 | 입력 대기 · 권한 요청 · 턴 종료(유휴)                               |
   - 상태가 바뀌면 원작 길찾기로 **걸어서** 이동, 도착한 방의 빈자리에 앉는다(고정 좌석 없음).
   - 도구 전환이 잦으므로 **같은 상태가 일정 시간(기본 ~3초) 유지될 때만** 방을 옮긴다 _(우리 판단)_.
   - 권한 요청은 대기실 안에서 ❗ 표시로 눈에 띄게 _(우리 판단)_.

3. **hover 말풍선** — 평소엔 말풍선 없음. 캐릭터에 마우스를 올리면 지금 하는 일을 요약해 보여 준다:
   - 수정: 어떤 파일을 어떤 이유로 (이유 = 해당 도구 호출 직전 에이전트가 남긴 설명 텍스트, 한두 줄로 자름)
   - 검색/읽기: 어떤 자료·검색어·사이트
   - 명령: 명령 설명(Claude Bash 의 `description`) 또는 명령 요약
4. **자식 캐릭터** — 세션의 **서브에이전트**와 **백그라운드 셸**은 각각 전용 외형의 캐릭터로 추가 표시.
   - 자식은 **자기 상태에 맞는 방으로 간다** (부모가 대기실, 서브에이전트가 코딩 중이면 서브에이전트는 코딩실).
   - **같은 방에 있으면 부모와 손을 잡고 줄지어** 다닌다. **다른 방에 있으면** 그 방에 부모의 **반투명 분신**이 나타나 자식 줄의 **가장 왼쪽에서 손을 잡고** 선다(실제 부모는 자기 방에 불투명하게 있음). 연결선은 그리지 않는다.
   - 자식에 hover 하면 그 자식의 작업 내용이 따로 보인다. 작업이 끝나면 사라진다.
5. **상세 내용 숨기기** (PC 별 옵션, 리포터 쪽에서 적용 → 민감 정보는 **내 PC 밖으로 나가지 않음**):
   - 숨김: 파일 경로·디렉터리, 사용자명/홈 경로, IP·호스트명, URL 의 경로·쿼리, 토큰·키처럼 보이는 문자열.
   - 유지: 작업 내용(이유·설명·검색 주제), 파일 이름(basename) _(우리 판단 — 경로만 위험하다고 봄)_, 방, 상태.
   - **기본값 켜짐** _(우리 판단)_. 켜져 있어도 **내 PC 의 localhost 화면**에는 내 에이전트를 전체 상세로 보여 준다. 네트워크 패킷과, 다른 PC 가 내 `http://IP:포트` 로 연 화면에는 필터된 상태만 나간다(로컬 원본/필터본 두 벌 유지, 요청 출처가 loopback 인지로 구분).
6. **지도 조작** — 빈 곳을 **왼쪽 버튼으로 잡고 끌면 지도 이동**, **마우스 휠은 확대/축소**(커서 위치 기준). 원작은 가운데 버튼 이동 + 줌 버튼이므로 변경. 캐릭터 클릭/hover 는 그대로 동작해야 한다. 픽셀이 뭉개지지 않는 줌 단계는 빌더 판단.
7. **내 프로필** — 첫 실행(및 설정)에서 **닉네임**과 **캐릭터 외형**을 고른다. 원작 동봉 캐릭터 6종 중 선택 + 원작의 색상 변형 사용 가능.
   - 고른 외형이 **내 메인 에이전트 캐릭터 전부**에 적용된다(Claude/Codex 구분은 이름표 아이콘으로) _(우리 판단)_. 서브에이전트·셸은 전용 외형.
   - 닉네임·외형은 패킷에 실려 다른 PC 에도 그대로 보인다.
8. **설치 파일 하나** — Windows(.exe 설치) · Mac(설치 패키지). Node 등 사전 설치 불필요. 첫 실행 시 닉네임 입력, 로그인 시 자동 시작, 트레이/메뉴바 또는 브라우저로 사무실 열기.
9. **배포·업데이트 = GitHub** — 공개 저장소 `github.com/YOOJUNGYU/pixel-office-lan`. 버전 태그(`v*`) push → GitHub Actions 가 Windows `.exe`·Mac `.pkg` 를 빌드해 **GitHub Release** 에 올린다. 앱은 주기적으로 최신 Release 를 확인해 새 버전이 있으면 화면에 "새 버전이 있습니다 → 업데이트" 버튼을 띄우고, 누르면 설치 파일을 받아 실행한다(자동 무음 설치 안 함 — UAC 창이 갑자기 뜨지 않게). 원작은 `upstream` 원격으로 연결해 변경을 받아올 수 있게 한다.
10. **언어: 한국어/영어** — 보는 사람마다 설정(브라우저 저장, 기본은 브라우저 언어). 방 이름·활동 문구·이름표·메뉴가 번역되고, 에이전트가 쓴 이유·파일명·명령은 원문. 이를 위해 네트워크에는 완성 문장 대신 `{act, target}` 을 보낸다. UI 글꼴은 Pretendard(OFL, 앱에 동봉).
11. **지원 환경** — Claude Code: Windows 네이티브 · WSL · Mac. Codex: 동일하게 세 환경.

## 3. 비목표 (이번 범위 아님)

- 다른 사람의 터미널 열기·에이전트 실행·승인·설정 변경 — **절대 공유하지 않는다.** 공유는 상태(읽기 전용)뿐.
- VS Code 확장 — 브라우저(standalone) 방식만.
- 사무실에서 에이전트 실행(원작의 + Agent / 임베디드 터미널) — 제거.
- 레이아웃 동기화 — 각 PC 가 자기 레이아웃으로 그린다(4개 방이 칠해진 기본 레이아웃을 동봉). 방 이름만 같으면 된다.
- 서브넷을 넘는 자동 탐색, 인터넷 경유 공유.
- 인증/계정 체계.

## 4. 안티 목표 (돌아가도 실패로 보는 것)

- 다른 PC 에서 내 PC 의 무언가를 **실행·변경**할 수 있게 되는 것.
- 숨기기 옵션을 켰는데 경로 등이 네트워크로 새는 것.
- 사용자의 `~/.claude/settings.json`·Codex 설정을 몰래 수정하는 것 (그래서 훅 대신 기록 파일을 읽는다).
- 설치에 개발 지식(npm, PATH, 터미널 명령)이 필요한 것.
- 캐릭터가 방 사이를 쉴 새 없이 왕복해 정신없는 것.

## 5. 구조 (결정됨)

### 5.1 서버 없는 P2P

설치된 모든 PC = **리포터 + 화면**. 중앙 서버·리더 선출·서버 승계 없음.

```
[A PC] 리포터+화면 ◀── UDP 브로드캐스트 (1초마다 내 상태) ──▶ [B PC] 리포터+화면
                  ◀────────────────────────────────────────▶ [C PC] ...
```

- 각 PC 는 자기 에이전트 상태를 같은 서브넷에 **UDP 브로드캐스트**하고, 받은 상태를 모아 로컬에서 사무실을 그린다.
- 일정 시간(예: 5초) 소식이 없는 PC 의 캐릭터는 사라진다. 누가 꺼져도 나머지는 영향 없음.
- 서브넷이 갈리는 경우를 위해 **상대 IP 수동 등록**(유니캐스트로 같은 패킷 전송)도 지원.
- 화면은 로컬 HTTP 서버가 브라우저로 제공. 미설치자는 아무 설치 PC 의 `http://IP:포트` 로 **구경만** 가능.
- 네트워크로 받는 패킷은 신뢰 경계 — 스키마 검증·크기 제한·문자열 이스케이프 필수(받은 텍스트를 HTML 로 그대로 넣지 말 것).

### 5.2 상태 수집 — 기록 파일 읽기 (훅 미사용)

| 에이전트         | 위치                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| Claude (Win/Mac) | `~/.claude/projects/**/*.jsonl` (서브에이전트 기록 포함)                                                     |
| Claude (WSL)     | Windows 리포터가 `\\wsl.localhost\<배포판>\home\<사용자>\.claude\projects` 도 읽음 (WSL 쪽 별도 설치 불필요) |
| Codex            | `~/.codex/sessions/**/*.jsonl` (WSL 도 위와 같은 방식)                                                       |

- 원작의 휴리스틱 모드(`server/src/transcriptParser.ts`, `fileWatcher.ts`)를 재사용·확장한다.
- 지연 약 1초 허용. 입력 대기/권한 요청 판정은 원작 휴리스틱(타이머 기반)을 따른다.
- 세션 = 에이전트 하나. 번호(`#1`, `#2`)는 PC 안에서 세션 시작 순.
- **표시 대상**: 기록 파일이 최근 30분 안에 바뀐 세션 _(우리 판단)_. 30분간 변화가 없으면 대기실에서 사라진다(Claude/Codex 는 종료를 기록하지 않으므로 파일 변화가 유일한 신호).
- 패킷에 프로토콜 **버전 필드**를 둔다 — PC 마다 버전이 달라도 모르는 버전은 무시하거나 호환 처리 _(우리 판단)_.

### 5.3 원작에서 가져오는 것 / 바꾸는 것

- **유지**: `webview-ui` Canvas 엔진(렌더러·길찾기·캐릭터 상태머신·레이아웃 에디터·에셋), 기록 파서, Fastify 정적 서빙.
- **추가**: P2P 브로드캐스트, 방 이동 로직(Areas 를 방으로 사용), 이름표, hover 말풍선, 자식 캐릭터(손잡기·연결선), 숨기기 필터, Codex 파서, WSL 경로 탐색, 닉네임/설정 UI, 설치 패키징.
- **제거**: VS Code 어댑터, pty/임베디드 터미널, 에이전트 실행, 훅 설치기·동의 흐름.

## 6. 규모와 제약

- **규모**: 약 20명 × 1인당 에이전트 ~5개 = 메인 캐릭터 ~100, 서브에이전트·셸 포함 동시 수백 캐릭터 가능.
  - 기본 레이아웃은 이를 수용할 만큼 크게(원작 상한 64×64 타일). 방에 빈자리가 없으면 방 안 빈 바닥 타일에 **서서** 있는다 _(우리 판단)_.
  - PC 당 패킷이 MTU 를 넘을 수 있으므로 에이전트 단위 등으로 나눠 보낸다.
  - 캐릭터 수백 개 + 연결선이 Canvas 에서 버벅이지 않아야 한다(성능 확인 필요).
- **코드 서명 안 함**. 사용자가 설치 중 허용하는 방식으로 배포:
  - Windows: SmartScreen "추가 정보 → 실행" → UAC 관리자 승인 → 설치기가 방화벽 인바운드 규칙(UDP 포트, HTTP 포트) 추가.
  - Mac: 첫 실행 차단 시 "시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기", 이후 macOS 방화벽의 "들어오는 연결 허용" 승인. 설치 안내 문서에 스크린샷으로 안내.
  - 회사 보안 솔루션(AppLocker·EDR 등)이 막는 경우는 범위 밖 — IT 예외 요청으로 해결.

- Windows 10+/Mac. 사용자 PC 에 Node·Python 없음을 전제.
- 회사망: Windows 방화벽이 UDP 수신 허용을 물을 수 있음(설치 시 규칙 추가 또는 안내). 와이파이 클라이언트 격리·VLAN 이면 브로드캐스트가 막힐 수 있음 → 수동 IP 등록으로 대응.
- Mac 미서명 앱은 Gatekeeper 경고 — 서명 여부는 배포 시 결정.
- 원작 MIT 라이선스 고지 유지. 캐릭터 에셋 출처(JIK-A-4 Metro City) 표기 유지.

## 7. 빌더에게 맡기는 것

- 패키징 방식(Node SEA / Electron / 기타)과 설치기 도구, 자동 시작 방식, 트레이 유무.
- UDP 포트 번호, 패킷 포맷·분할(에이전트가 많을 때 MTU 초과 처리), 만료 시간 값.
- 도구 → 방 매핑의 세부(MCP 도구 등 미분류 도구 처리), 방 이동 완충 시간 값.
- 서브에이전트/백그라운드 셸 감지 방법(Claude·Codex 각각 기록 포맷 확인 후).
- 서브에이전트·셸 캐릭터 외형, 손잡기·연결선 그리기 방식.
- 숨기기 필터의 정확한 패턴(위 5번 범주를 만족하면 됨).
- 기본 레이아웃(4개 방)의 모양.
