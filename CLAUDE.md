# Pixel Office LAN — Reference

Fork of pixel-agents: a pixel-art office in the browser where coding agents on every PC of a LAN appear as characters. Standalone Node server + browser SPA only (no VS Code extension, no terminal).

LAN design and the task plan: `docs/superpowers/specs/2026-10-21-pixel-office-lan-design.md`, `docs/superpowers/plans/2026-10-21-pixel-office-lan.md`. `CONTEXT.md` is the upstream glossary (partly stale; the spec wins).

## Quitting

Tray **Quit** and Settings → 완전 종료 (`quitApp`, privileged) both call `shutdown(true)`: every UI socket is closed with `WS_CLOSE_APP_QUIT` (4010, `core/src/constants.ts`) so the page stops reconnecting and shows `conn.quit` (the transport's `disconnected` state now only means this), then exit 0 (a restart into a silent update exits 75 under the LaunchAgent instead, so it respawns) — the LaunchAgent's `KeepAlive {SuccessfulExit: false}` does not respawn a clean exit (crashes still restart). Neither path writes the updater's reopen marker: that is `POST /api/quit` (`Updater.onQuit`) only, whose pages keep reconnecting to reload into the new version. A quit page (and a page that never connected) shows `ServerPanel` with [시작].

## Silent updates

The installers need admin rights, but the app is Node + `dist/`, so a release's `dist/` ships as one more asset, `PixelOffice-<ver>-node-<node-version.txt>-app.tgz` (+ `.sha256`; plain ustar, `app.json` = `{version, node}` inside; built in package.yml's build job; never matches `ASSET_NAME`). `Updater.check` → `checkForUpdate` also picks the bundle for this exact `process.version` (`pickAppAsset`) → always (forced since 1.0.10: no toggle; an old `config.json standalone.autoUpdate` is ignored): `stageAppUpdate` (URL via `repoUrl` on github.com only; size = API size ≤ 100 MB; SHA-256 = API `digest`, else the `.sha256` asset, none → refuse; gunzip ≤ 400 MB; `readTar` takes only regular files/dirs, rejects absolute/drive/`..`/backslash paths and links; unpack to `app/.<ver>.partial`, manifest must match, rename to `app/<ver>`; prune to the newest 2 newer than installed + the running one) → restart (`restartMode`): macOS LaunchAgent (launchd sets `XPC_SERVICE_NAME=com.pixeloffice.agent`) → exit 75 so KeepAlive respawns; Windows / the Mac app → after `server.stop` spawn the installed `argv[1]` detached (no `--open`), exit 0; Linux/dev → applied at the next start (`PIXEL_OFFICE_UPDATE_RESPAWN=1` respawns, tests). Any failure or a Node mismatch → today's banner + installer. Open pages reconnect and reload (`officeAccess.version`); the banner shows `update.updated` once (localStorage `pixel-office.seenVersion` older than the bundle). Boot: `main(boot=true)` in the installed cli.js calls `bootUpdated(APP_VERSION)` before the single-instance check: newest `app/<ver>` newer than installed, not `app/bad-<ver>`, `app.json` = ver + this Node, `cli.js` present → `require` it and run its exported `main(false)` in this process (argv/execPath unchanged, so tray/autostart paths stay the installed ones). Rollback = strikes (`app/strikes-<ver>`, 2 in a row → `bad-<ver>`), only for failures the bundle causes: a throw while loading (the installed main continues), an uncaught exception (`uncaughtExceptionMonitor`, also a rejected main) before it has run 3 min after listening (`reportListening` → `globalThis.pixelOfficeListening`; then strikes are cleared = healthy), no listen within 180 s; each restarts (respawn / launchd). Explicit exits (already running, port busy, EACCES bind) are no strike. The strike file is written before booting: unwritable app dir → no update is booted; an unrecorded timeout exits 0. A bad version is never booted or downloaded again; a failed stage of a version is not retried for 24 h (the rename into place is retried 5×, Windows AV); prereleases boot only with `PIXEL_OFFICE_ALLOW_PRERELEASE=1`. The test-only API override stays in production builds (honoured only for loopback http). Tests: `server/__tests__/lan/appBundle.test.ts`, end to end `autoUpdate.e2e.test.ts` (fake API via `PIXEL_OFFICE_UPDATE_API`, honored only for http://127.0.0.1|localhost, downloads then from that origin). Users on ≤ 1.0.0 need the 1.0.0 installer once. `PixelOfficeTray.exe` and the rest of the install dir (node.exe, PixelOffice.exe, icon) are outside the bundle: a change to them needs an installer release.

## Handshake (`webviewReady`)

`officeAccess {readOnly, version}` (readOnly always false in practice; safety net; also sent on every WS connect so a reconnected page learns the server version) → asset messages (characters, pets, floor, walls, carpets, furniture) → `settingsLoaded` → `profileLoaded {profile, canEdit, account, firstRun}` → `officesState` (names, never secrets/codes) → `layoutLoaded` (saved layout, else bundled default; rooms normalized) → first `officeSnapshot` → `autostartState` → `updateAvailable` (when known). Privileged-only parts are skipped for a read-only ctx. After that `officeSnapshot {agents, people, online, selfPeerId}` (`online` = live people per open office, me included — in personal mode only the others heard, `PeerNet.liveCount`; `LanService.online()`, the counts on the switcher tabs) (`people` = every PC live in that office, agents or not, self first, with its active `chat` and its `avatar {col,row,dir}` if any — the right-edge people panel and the avatars, `webview-ui/src/lan/PeoplePanel.tsx` + pure `peopleModel.ts`) is pushed every second to every socket (this PC's agents verbatim; what goes to peers is always redacted: `views(brief=true)` + `redactView`, and with `profile.hideWork` (Settings → 내 작업 내용 숨기기, default off) `hideView` instead: room/provider/kind/tree/permission only, act `idle` + `hidden: true` (old peers know `idle`), no target/reason; viewers show `act.hidden`. A pre-1.0.9 profile's `hideDetails` is ignored). Names: `PeerInfo`/`people` carry `account` + optional `nickname`; name tags (avatars and agents, `avatarLabel`) show the nickname alone when set, else the account; the people panel and notifications use `peerLabel` = `account (nickname)` (`webview-ui/src/lan/nicknames.ts`; a 0.3.x peer without `account` gets its nickname or short id as account and an empty nickname). Nicknames are unique per visible channel: `saveProfile` with one another live visible peer uses (`nicknameKey`: NFC, trim, case/whitespace-insensitive) → `profileError {nicknameTaken}` + unchanged `profileLoaded`; collisions that slip through are tie-broken per viewer: whoever set the nickname first keeps it (`profile.nicknameSince` → `PeerInfo.nickSince`, missing = loses; then smaller peerId), others get ` · <4 id chars>` on the nickname; a nickname equal (`nicknameKey`) to another's account tag shows `nickname (account)` (`withAccount`), a shared account without nickname gets the suffix on the account; a nickname equal to the account is not repeated in the label. The loser sees a rename notice once per clashing nickname (localStorage). Received nicknames are stripped of control/bidi/format chars. Character: `palette` 0–5 (human) + `hueShift`, and optionally `pet` (`claudio`|`gitcat`, `PET_IDS` in `core/src/lan.ts`; unknown ids are dropped by `parsePeerPacket`/`validateProfileUpdate`, and an older peer that drops the field shows the palette human). A pet character uses the pet sheet (walk cycle when walking, idle loop otherwise, hue-shifted without skin exemption); subagents and shells look exactly like their PC's character (`looks`; the MAIN/SUB/SHELL badge tells them apart). Office replies (`officeCreated`, `officeCode`, `officeError {reason}`) go to the requesting socket only; `officesState` + a fresh snapshot follow every office change, and `officesState` is re-sent when a member announces a team's name.

## Privilege rule (this PC only)

The UI is served to this PC's browser only (remote viewing was removed in v0.4.0). The CLI binds `127.0.0.1` by default, and every HTTP request (`/api/ping` and `POST /api/quit` included) gets 403 and `/ws` closes with 4003 unless `isLoopback(req)` (`server/src/httpServer.ts`):

- remote address is `127.0.0.1`, `::1` or `::ffff:127.0.0.1`, AND
- `Host` header host is `localhost`, `127.0.0.1` or `[::1]`, AND
- `Origin`, if present, has the same host as `Host`.

This holds regardless of `profile.json` (a pre-0.4 `remoteView` key is dropped on load). Safety net: `ctx.privileged` (defaults to false) still drives the single gate at the top of `handleClientMessage`, which refuses every message except `webviewReady` (new message types are privileged by default) and re-sends the true state where the UI updated optimistically; the webview keeps a minimal "보기 전용" display for `officeAccess {readOnly: true}`. The office snapshot follows `profile.activeView`. Never execute or write anything based on data from peers (sole exception: the validated shared layout, see Shared layouts).

## Personal mode

`profile.activeView = 'personal'` (`PERSONAL_VIEW`, `core/src/lan.ts`; never a team tag — those are 11 chars) = this PC alone, offline. Chosen from the switcher's 🏠 tab (`setActiveView {view: 'personal'}`, privileged; any other unknown view is refused with officesState); public or a team tab switches back. Team memberships stay in profile.json (inactive), so switching back needs no code; `leaveOffice` keeps personal; create/join switch to the team. PeerNet `offline()` (cli.ts → `lan.personal`): `sendNow` sends nothing (no hello, no presence), `receive` only listens (no hello reply, no pub; team presence is still decrypted), `peers()` is empty, `liveCount(view)` = the others heard (public: live hellos, team: live presence) for the tab counts; `LanService.office/people` also skip peers. The snapshot = this PC's agents + self. My avatar and chat work and stay local (`view: 'personal'`, never on a channel; the avatar spot is kept separately as `profile.avatar.personal`). Layout: own file `layout-personal.json` + bundled `default-layout-personal.json` (`AssetCache.personalLayout`); `saveLayout`/`layoutLoaded`/Reset (webview `PERSONAL_LAYOUT_ASSET`) follow the current mode. Switching personal on/off sends `layoutLoaded` before `officesState` (`onOfficesChanged(layoutChanged)`), and the webview refits the camera from the default zoom when the mode changes (App fit effect keyed by `isPersonal(offices)`). Two-instance check: `.superpowers/personal/e2e.mjs` (local only).

## Shared layouts

Every PC in the public office (and in each team office) shows the same layout; anyone there can edit it, the last save wins (user decision, 1.0.14). Version `LayoutRev {rev, by, h}` (`core/src/lan.ts`; rev 0 = bundled default; newer = higher rev, then larger `by` peer id; `h` = 16 hex of SHA-256 of the layout JSON). A save (`saveSharedLayout`) = rev one above every version this PC knows (its own and peers' adverts). Each presence carries `PeerPacket.layout` (this PC's version of that channel; ≤ 1.0.13 peers send none and are never pushed to). PeerNet: a PC whose version is newer than a live peer's pushes the deflated JSON as `{lay: {rev, by, h, part, parts, d}}` plaintexts (`layoutPlains`, ≤ `MAX_LAYOUT_PARTS` × `LAYOUT_PART_BYTES`, sealed like presence: pub unicast per lagging peer / one team broadcast) at most every `LAYOUT_PUSH_MS` per target; the receiver assembles only a version newer than its own (one per channel, `LAYOUT_ASSEMBLY_MS`), inflates ≤ `MAX_LAYOUT_JSON`, checks `h`, then `LanService.receiveLayout` → `checkLayout` (= `sanitizeLayout` against the bundled default, set by httpServer) → `SharedLayouts.offer` → `layoutChanged` → `layoutLoaded` to the pages when it is the office on screen (the editor keeps unsaved edits: `isEditDirty`). This is the one exception to "never write data from peers": layout data only, validated, drawn — never executed. Every office switch re-sends `layoutLoaded` (`onOfficesChanged(activeView changed)`). Tests: `server/__tests__/lan/sharedLayout.test.ts`.

## Datagram size (split presence)

Every PeerNet datagram is ≤ `MAX_DATAGRAM_BYTES` (1200) on the wire: some networks (and WSL loopback) drop IP fragments, i.e. anything over 1472 B. `pub`/`team` presence whose datagram fits is sent in the old single form (the Inner `{seq, packet, office?}`, byte-identical to 0.4.x; one seq per send tick, shared by every pub peer). A larger one is deflated and split into ≤ 48 parts `{seq, from, part, parts, d}` (420 B each, inside the same seal/AAD); `fitPacket` trims trailing views until it fits. 0.4.x peers drop parts, so a busy PC is missing for them (documented in the install guides and README). The receiver keeps one assembly per (channel, sender), ≤ 256 in all, a newer seq replaces an unfinished one, unfinished ones expire after 2 s (the last complete state stays), the replay guard applies to complete seqs, and a complete one is inflated (≤ MAX_PACKET_BYTES) and must match the part header's seq and sender (pub: also the wire `from`).

## Data

`~/.pixel-office/` — `layout-personal.json` (the personal office's layout; never sent to peers), `layout-shared.json` (`lan/sharedLayout.ts` `SharedLayouts`: `{channels: {[public|tag]: {rev, by, layout}}}`, the newest shared layout per office; a legacy per-PC `layout.json` is ignored), `config.json`, `app/<ver>/` + `app/strikes-<ver>`/`bad-<ver>` (silent updates), `profile.json` (0600: X25519 key pair, team office secrets, optional nickname + `nicknameSince` (set when it changes; migrated = file mtime), `setUp` = first-run form saved; `chat` = my current chat bubble + its view; `avatar {office?, personal?}` = my avatar's `{col,row,dir}` per layout (layout.json vs layout-personal.json; malformed dropped on load); the OS account name is NOT stored — `LanService.account` = `osAccount()` at every start, `DOMAIN\` stripped, ≤32, else hostname; never settable by a client), `known-peers.json` (0600, TOFU peer id → public key). Ports: UDP 47800 (peers; the only inbound port — Windows firewall rule `protocol=UDP localport=47800`), HTTP 47801 (UI, this PC only); the CLI defaults to `--host 127.0.0.1 --port 47801` (`--host` is kept for dev; non-loopback requests are refused anyway). A UDP bind failure only disables peers. Two instances on one host (tests only): `PIXEL_OFFICE_UDP_PORT=47810 PIXEL_OFFICE_UDP_TARGETS=127.0.0.1:47811` and the mirror for the other.

Release notes start with a bilingual "which file" table (`--notes-file` + `--generate-notes`). Manual run → artifacts; tag `v<package.json version>` → GitHub Release (`-` in tag = prerelease); a non-prerelease release then deletes every other release and its tag, so only the latest exists. User guide: `docs/설치-안내.md`, `docs/INSTALL.en.md`.

## Conventions

- **Protocol**: edit `core/asyncapi.yaml`, run `npm run asyncapi:generate`; CI fails if `core/src/messages.ts` drifts. Every message sets `additionalProperties: false`.
- **Constants**: no inline magic numbers/strings. Server → `server/src/constants.ts`; protocol → `core/src/constants.ts`; webview → `webview-ui/src/constants.ts`; CSS variables in `webview-ui/src/index.css` `:root`.
- **Colors**: hex/rgb/hsl literals only in `webview-ui/src/constants.ts` (eslint `pixel-agents/no-inline-colors`, error level). Pixel style: `borderRadius: 0`, `2px solid` borders, hard `2px 2px 0px` shadows — except the speech bubbles (`.bubble-agent` slate 6px radius, `.bubble-chat` white 12px radius; tail = rotated square `::after` at the bottom centre; colours `--agent-bubble-*`/`--chat-bubble-*` in `index.css`), which are rounded on purpose and must stay visually distinct from each other. UI font Pretendard (`var(--font-ui)`, bundled `webview-ui/public/fonts/`, OFL; eslint `pixel-agents/ui-font`).
- **TypeScript**: no `enum` (use `as const`); `import type` for type-only imports; `.js` extensions on relative imports in `server/` and `core/`; `noUnusedLocals`/`noUnusedParameters` everywhere.
- **No new runtime dependencies** — UDP, file watching, paths via Node stdlib.
- **User-facing text via `webview-ui/src/i18n.ts`** (`t(key, params?)`, ko/en per viewer, `localStorage['pixel-office.lang']`, default from `navigator.language`). Agent activity travels as `{act, target}` and is rendered by each viewer; `reason`/targets are shown as-is. Layout room labels stay 코딩실, 자료실, 서버실, 대기실 (keys coding|library|server|lounge) and are translated only for display (`areaName`).
- Logging: `console.*` with `[Pixel Office]` (server) / `[Webview]` prefixes.
- Keep the upstream MIT LICENSE and the JIK-A-4 Metro City character credit.
- Commits: husky pre-commit runs gitleaks + lint-staged; never `--no-verify`.

## Office UI essentials

- Game state lives in the imperative `OfficeState` (not React). Zoom is a float (0.25–10, wheel = `wheelZoom`; first open fits the office below a `FIT_TOP_MARGIN_PX` band so the switcher never covers the room names); the frame is drawn at the integer `renderScale(zoom).renderZoom` (sprite caches stay per-integer) and blitted scaled — below zoom 1 only the visible map is rendered and the background is painted on screen; overlays/hit-tests use `mapOffset`/`overlayProjection` with the float zoom. No `ctx.scale(dpr)`, z-sort by Y. Floor/wall-base/carpets are cached in LRU chunks (~512 device px, `FLOOR_CACHE_MAX_PIXELS`; an edit drops only the chunks it touched, `office/engine/floorChunks.ts`); wall instances and room-name positions are cached per layout; off-screen furniture is culled. The canvas effect never re-runs per edit (a canvas width/height assignment clears it: only on a real resize).
- Layout model `{ version: 1, cols, rows, tiles, furniture, tileColors?, areas?, areaTiles?, background? }` (`background` = map fill outside the office/VOID tiles, `office/background.ts`; missing = page navy); grid ≤ 128×128 (`MAX_LAYOUT_COLS/ROWS`, `core/src/lan.ts`); the bundled default (`scripts/generate-lan-layout.mjs` → `default-layout-1.json`, deterministic) is 83×54 (top 코딩실 | 서버실, corridor, bottom 자료실 | 대기실; each column's two rooms have the same size; every room is a grid of furniture groups (`roomGrid`/`spread`) with the same free border on all four walls — 2 tiles; personal: 1 in 코딩실/자료실, 2 in 서버실/대기실 — the gaps spread evenly and mirror-symmetric, no corner decor; 자료실 also has bookshelves on its top wall (door left open; the upper tile over the corridor's last row); 코딩실 75 / 자료실 64 / 서버실 128 / 대기실 64 seats); `--personal` → `default-layout-personal.json`, 28×23, 8 seats per room (대기실 16) (same rooms/corridor, per-variant furniture counts in the script's `V`; `test/lanLayout.test.ts` checks both match the generator) and the size is fixed (no grid expansion in the editor; an imported/older layout of another size is shown as is; Settings → reset to the default office); saved via `saveLayout` from the editor (loopback only): personal → `layout-personal.json`; public/team → `LanService.saveSharedLayout` (see Shared layouts).
- Rooms are fixed: `areas` = exactly 코딩실/자료실/서버실/대기실 (`normalizeRoomAreas` in `core/src/lan.ts`: missing rooms added with default colors, unknown areas and their tiles dropped). Applied by the webview on `layoutLoaded`/import (`migrateLayout`) and by the server on save and load (`sanitizeLayout`, `server/src/layoutPersistence.ts`, which strips legacy `pets`). Room tiles come only from the default layout: a room without tiles takes the default's tiles when the grid is the default size (`fillMissingRooms`, server sanitize + webview import). Grid check shared by the server, the import and `layoutLoaded`: `isLayoutGrid` (v1, cols/rows ≤ 128, `tiles.length === cols*rows`, furniture array); a written `saveLayout` answers `layoutSaved` to the sender (the editor's [Save] leaves edit mode only on it, `office/editor/saveFlow.ts`; no answer in 5 s → error toast), a refused or unwritable one `layoutSaveRejected` (toast). A missing room color falls back to `ROOM_DEFAULT_COLORS`. There is no area tool; a room with no walkable tile is warned about in the editor.
- Layout editor: floor/wall/erase/furniture/background tools, 50-level stroke-scoped undo, Esc unwinds in stages; pure ops in `office/editor/editorActions.ts`. Reset/Undo/Redo/Save/Cancel (`EditActionBar`) sit right of the bottom-left toolbar while editing. No autosave: edits live only in the page until [Save] (`handleSave` → `saveLayout` → `layoutSaved`, then history cleared and the editor closes); [Cancel], Esc's last stage and the Layout button while editing all go through `cancelEditing` (confirm when dirty) → `handleCancel(savedLayoutRef.current)` = back to the last saved layout (`useExtensionMessages` keeps it from every `layoutLoaded`, even one skipped while dirty, and from this page's saves/imports). [Reset] puts the bundled default in as one undoable edit (`handleResetTo`); Settings → reset/import still save at once.
- Avatars (`OfficeState.addAvatar`/`walkAvatarTo`/`pressAvatar`, `LanAgents.applyPeople`): every live person of the viewed office (`people`, me included, personal mode too) has exactly one avatar character with their profile look (`Character.avatarOf` = peerId), separate from their agents; never seated, never hit-tested (`getCharacterAt` skips them), not counted on room plates. Mine walks with the arrow keys (`lan/avatarKeys.ts`; not while a text field has focus, editing, touring, read-only): one tile per press onto walkable tiles only (walls/void/blocking furniture block, characters don't), held = keeps walking (`update()` queues the next step on arrival; `nextFrameIn` = 0 while held), a blocked press just turns. Each step/turn → `moveAvatar {col,row,dir}` (privileged; `parseAvatar(raw, true)`: integers 0..127, dir ∈ `AVATAR_DIRS`) → `profile.avatar[office|personal]` (file write coalesced to `AVATAR_SAVE_DELAY_MS`) and a presence send coalesced to `AVATAR_SEND_DELAY_MS` (≤ 5/s, tiny: `PeerPacket.avatar`, office layout only). PeerNet's `onAvatar` (a peer's avatar changed) → `LanService.peerMoved` → httpServer pushes an extra snapshot (same coalescing). My avatar is placed once from the snapshot (none → a free lounge tile, unwalkable → the closest walkable tile; either way sent back as moveAvatar), again after every `layoutLoaded` (`resetSelfAvatar`, mode switch/reset); later snapshots never pull it back. Remote avatars walk (`findPath`) to their latest spot (peer coords `parseAvatar` rounded + clamped, then onto my layout), teleport when no path or > `AVATAR_TELEPORT_TILES`, then face `restDir`. Avatar name tag = one line, nickname (tie-broken) else account (`avatarLabel`), always shown (the toggle, "이름표·말풍선", hides agents' tags only: `tagVisible(…, avatar)`), background/text = the person's `tagColors {bg, fg}` (profile pickers; `#RRGGBB`, `parseTagColors` in `core/src/lan.ts` on save and on receive; travels in `PeerInfo`/`people`; absent = `--avatar-tag-bg`/`--avatar-tag-fg`), mine framed by `--avatar-tag-self-border` (both themes in `index.css`); avatar tags take part in `stackTags`.
- Lounge = people only: an agent whose room is `lounge` has no character when its PC's avatar is shown (`LanAgents.reconcile`; no avatar — tour demos — keeps the old lounge seat). Leaving the lounge it steps out of the avatar (`OfficeState.departFrom`, no spawn effect; on the first snapshot after load agents are placed directly), going back it walks to the avatar and vanishes beside it (`mergeAgent` → `Character.mergeInto`, handled in `update()`). A folded agent waiting (`permission` or act `ask`, `LanAgents.waitingPeers`) puts the red ! over the avatar. Avatars walk anywhere walkable (`avatarMayStand`; a new avatar starts on a free lounge tile, an unwalkable saved spot moves to the closest walkable tile in any room) but sit only on lounge chairs. An arrow step onto a free lounge chair (`avatarSeat`) claims it and sits (state TYPE, still, facing the desk; `moveAvatar` reports the chair tile + its facing); the next press toward open floor stands up (held keys never stand it up; blocked = stays seated); a remote/saved spot on a chair is shown seated (`settleAvatar`/`claimAvatarSeat`); ≤ 1.0.4 peers move it to the closest floor tile. Agent name tag = one line under the character: MAIN/SUB/SHELL badge, `#n` (a child shows its parent's), nickname else account (`tagText`). With tags & bubbles shown (the top-left toggle "이름표·말풍선", default shown: localStorage `pixel-office.tagsHidden` = '1' only after hiding), every working agent also has a speech bubble above its head (`.bubble-agent`, tail to the head; the white `.bubble-chat` is people's chat): Claude/Codex badge (`providerName`, `LAN_PROVIDER_COLORS`) + `activityText` (a run shows the command alone — its room says it), truncated at `LAN_ACTIVITY_MAX_WIDTH_PX`, stacked with `stackBubbles`; hover still shows the full bubble.
- Agent characters never wander: a seated character stays seated (still when idle), a seatless one stands still; walking only happens between rooms or when following a leader (`updateCharacter`). Every character (main, subagent, shell) is placed by its own state/room; a child in the same room as its parent holds its hand (`setFollowTarget`), one in another room acts on its own (no ghost parents). Room name plates are DOM badges (`lan/RoomPlates.tsx`, pixel-panel, fixed font) just inside each room's top-left tile (first tile of the area in reading order), placed through `overlayProjection` and recomputed on `onFrame` (re-rendered only when a plate moved or its text changed); with a count chip `에이전트 8` when agents are there (never on 대기실: people only) (main agents and children together, each by its own room; `roomCounts`/`plateCount`, `OfficeState.roomCounts`; none = no chip). There is no Show Areas setting any more (removed with `setShowAreas`; the plates are the room display).
- On-demand rendering (`office/engine/gameLoop.ts`): a frame runs only after `requestRender(reason)` or when `OfficeState.nextFrameIn(nowSec)` says the scene animates — 0 = every rAF (walk, matrix effect, IDLE about to path, camera glide), N s = one timer wake at the next boundary (typing frame, pet idle frame, follow retry, animated furniture), Infinity = asleep. Requests come from: any window input event (OfficeCanvas), every server message, `LanAgents.reconcile` (snapshots/demos), `highlightPeer`, `selectedAgentId`, `rebuildFromLayout`, resize, fonts, `subscribeTheme`, tour steps, and an App-level effect after every App render (safety net). New state the canvas or overlays show that changes outside these paths MUST call `requestRender`; a new self-animating thing MUST be reflected in `nextFrameIn`. `LanOverlay` re-renders via `onFrame` (skipped on pure timer wakes); TourOverlay keeps its own rAF while the tour runs. Tests: `test/renderScheduler.test.ts`; perf scripts in `.superpowers/perf/`.
- Chat (`lan/ChatLayer.tsx`, pure `lan/chat.ts`): the chat bar at the bottom centre (shown when I am in the viewed office's snapshot, `people` has `self`; hidden while editing, touring, read-only, touch). Enter in it sends `sendChat {text}` (privileged) and keeps focus; Esc blurs it (arrows move the avatar again); Space+Enter (Space held) with nothing focused (body/canvas) focuses it; the placeholder names the shortcut and the arrow keys. ≤ `CHAT_MAX_CHARS` (100) code points, 1 per `CHAT_MIN_INTERVAL_MS` (2 s) in the webview and the server. One bubble per PC, no expiry: `LanService.sendChat` replaces `profile.chat {id, text, ts, view}` (persisted in profile.json; dropped on load if malformed or its view is not open, and by `update()` whenever its view stops being open — leaving the team, or joining one for a public chat; a pre-avatar `col`/`row` is dropped); `deleteChat` (privileged, the × on my bubble or next to the bar) clears it; both answer the sender with a fresh `officeSnapshot` (no local echo). `chat {id, text, ts}` (`PeerPacket.chat`, `parseChat`: `cleanChatText`; an older peer's `col`/`row` ignored — but ≤ 1.0.0 peers drop ours, which has none) goes only into that view's channel presence (`getPacket(channel)`); the snapshot's `people[].chat {id, text}` is each live person's current one. The webview (`ChatBubbles.apply`) rebuilds the bubbles from every snapshot, draws each above its owner's avatar head (it follows the avatar), wraps text (`wrapLines`), stacks overlapping bubbles upward (`stackBubbles`) with a tail to the head. Two-instance Playwright check: `.superpowers/avatar/e2e.mjs` (local only; walk, chat, follow, delete, tag colours, screenshots).
- PC notifications (server `lan/notify.ts`, OS notifications through the tray helper — no in-app toast): join/leave = public office only, `PresenceWatcher` diffs consecutive ticks' `lan.people(activeView)` by peerId (self ignored, label `peerLabel`, now in `core/src/lan.ts`); reset when `profile.activeView` changes (and at start); people seen within `PRESENCE_SETTLE_MS` (5 s) of the first tick after a reset are baseline; a leave is reported by the first tick ≥ `PRESENCE_LEAVE_GRACE_MS` (10 s) after it, dropped if the peer is back; several at once → one "N명" notification. My agents = `scanner.views()` main agents only, every view: an id seen for the first time is baseline; waiting (`permission` or act `ask`) false→true once; done = busy → idle in the lounge (displayed room, so `ROOM_DEBOUNCE_MS` filters a turn that restarts at once); a vanished session says nothing. Text: `Claude #1 · <folder>` + newline + `<title> — 응답을 기다립니다 (ctx)` (title ≤ `NOTIFY_TITLE_MAX`; merged events one line each, `NOTIFY_TITLE_SHORT_MAX`; no title = `Claude #1 · <folder> — …`). Title (`Scanner.info(id)`): Claude `custom-title` > latest `ai-title` > first real prompt; Codex `session_index.jsonl` thread name (last line per id; next to each codex root, re-read only when mtime/size changes, last `CODEX_INDEX_MAX_BYTES`) > first user message; folder = basename of the cwd. All picked up from tailed lines into `SessionState.local` — LOCAL ONLY: never in `toViews`/AgentView/PeerPacket (scanner.test checks the packet). `Notifier` takes the `Scanner` itself (`local: Scanner`, nominal via private fields) so the office snapshot with peers' agents cannot be wired in, and `AgentWatcher` skips any view carrying `peer`. Settings → two toggles (`settings.notifyPresence`, `settings.notifyAgents`).
- Top right is one stack (no overlaps): update banner, install popup, people panel (takes the height left). Top left (`components/ZoomControls.tsx`): the dark/light toggle (`data-tour="theme-toggle"`, sets an explicit dark/light even when the pref is `system`; also on mobile), + and − in the same row (`data-tour="zoom"`, desktop only), then the name-tag toggle at `TAG_TOGGLE_TOP_PX` (`lan/TagToggle.tsx`, hidden while editing). Hovering a plate opens its popup (`RoomTip`): what sends an agent there (`legend.<room>`), then one card per agent in the room (`roomAgents`: per PC, main then children; folded lounge agents included) — face thumbnail, MAIN/SUB/SHELL + `tagText`, provider badge + `actText` (red ! when waiting); kept inside the room's screen box (width ≤ `ROOM_TIP_WIDTH_PX`, height to the room's bottom, scrolls). The tour's room step forces the first plate's popup.
- Theme (per viewer, `src/theme.ts`, localStorage `pixel-office.theme`: dark default = the original look, light = near-white chrome and a lifted office, system): `<html data-theme>` re-points the CSS variables in `index.css` (`:root[data-theme='light']`); the canvas reads `getTheme()` every frame and maps floors/walls/furniture/background through `office/themeColors.ts` (pure per-pixel HSL transforms, `LIGHT_THEME_TRANSFORMS`, cached per sprite; floor chunks and wall instances keyed by theme; characters/pets never transformed). Never a CSS/canvas `filter` (pixel-crisp; `test/theme.test.ts` scans for it).
- Assets: per-furniture `manifest.json` under `webview-ui/public/assets/furniture/`, characters `char_0..5.png`, floors, walls, carpets, pets.
