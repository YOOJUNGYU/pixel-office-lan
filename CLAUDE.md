# Pixel Office LAN — Reference

Fork of pixel-agents: a pixel-art office in the browser where coding agents on every PC of a LAN appear as characters. Standalone Node server + browser SPA only (no VS Code extension, no terminal).

LAN design and the task plan: `docs/superpowers/specs/2026-10-21-pixel-office-lan-design.md`, `docs/superpowers/plans/2026-10-21-pixel-office-lan.md`. `CONTEXT.md` is the upstream glossary (partly stale; the spec wins).

## Quitting

Tray **Quit** and Settings → 완전 종료 (`quitApp`, privileged) both call `shutdown(true)`: every UI socket is closed with `WS_CLOSE_APP_QUIT` (4010, `core/src/constants.ts`) so the page stops reconnecting and shows `conn.quit` (the transport's `disconnected` state now only means this), then exit 0 — the LaunchAgent's `KeepAlive {SuccessfulExit: false}` does not respawn a clean exit (crashes still restart). Neither path writes the updater's reopen marker: that is `POST /api/quit` (`Updater.onQuit`) only, whose pages keep reconnecting to reload into the new version.

## Handshake (`webviewReady`)

`officeAccess {readOnly, version}` (readOnly always false in practice; safety net; also sent on every WS connect so a reconnected page learns the server version) → asset messages (characters, pets, floor, walls, carpets, furniture) → `settingsLoaded` → `profileLoaded {profile, canEdit, account, firstRun}` → `officesState` (names, never secrets/codes) → `layoutLoaded` (saved layout, else bundled default; rooms normalized) → first `officeSnapshot` → `autostartState` → `updateAvailable` (when known). Privileged-only parts are skipped for a read-only ctx. After that `officeSnapshot {agents, people, selfPeerId}` (`people` = every PC live in that office, agents or not, self first, with its active `chat` if any — the right-edge people panel, `webview-ui/src/lan/PeoplePanel.tsx` + pure `peopleModel.ts`) is pushed every second to every socket (this PC's agents verbatim; `hideDetails` only redacts what goes to peers). Names: `PeerInfo`/`people` carry `account` (always shown) + optional `nickname`, label `account (nickname)` (`webview-ui/src/lan/nicknames.ts`; a 0.3.x peer without `account` gets its nickname or short id as account and an empty nickname). Nicknames are unique per visible channel: `saveProfile` with one another live visible peer uses (`nicknameKey`: NFC, trim, case/whitespace-insensitive) → `profileError {nicknameTaken}` + unchanged `profileLoaded`; collisions that slip through are tie-broken per viewer: whoever set the nickname first keeps it (`profile.nicknameSince` → `PeerInfo.nickSince`, missing = loses; then smaller peerId), others get ` · <4 id chars>` on the nickname; identical labels suffix the account; a nickname equal to the account is not repeated in the label. The loser sees a rename notice once per clashing nickname (localStorage). Received nicknames are stripped of control/bidi/format chars. Character: `palette` 0–5 (human) + `hueShift`, and optionally `pet` (`claudio`|`gitcat`, `PET_IDS` in `core/src/lan.ts`; unknown ids are dropped by `parsePeerPacket`/`validateProfileUpdate`, and an older peer that drops the field shows the palette human). A pet character uses the pet sheet (walk cycle when walking, idle loop otherwise, hue-shifted without skin exemption); subagents of a pet owner are the same pet hue-offset, shells keep the shell look. Office replies (`officeCreated`, `officeCode`, `officeError {reason}`) go to the requesting socket only; `officesState` + a fresh snapshot follow every office change, and `officesState` is re-sent when a member announces a team's name.

## Privilege rule (this PC only)

The UI is served to this PC's browser only (remote viewing was removed in v0.4.0). The CLI binds `127.0.0.1` by default, and every HTTP request (`/api/ping` and `POST /api/quit` included) gets 403 and `/ws` closes with 4003 unless `isLoopback(req)` (`server/src/httpServer.ts`):

- remote address is `127.0.0.1`, `::1` or `::ffff:127.0.0.1`, AND
- `Host` header host is `localhost`, `127.0.0.1` or `[::1]`, AND
- `Origin`, if present, has the same host as `Host`.

This holds regardless of `profile.json` (a pre-0.4 `remoteView` key is dropped on load). Safety net: `ctx.privileged` (defaults to false) still drives the single gate at the top of `handleClientMessage`, which refuses every message except `webviewReady` (new message types are privileged by default) and re-sends the true state where the UI updated optimistically; the webview keeps a minimal "보기 전용" display for `officeAccess {readOnly: true}`. The office snapshot follows `profile.activeView`. Never execute or write anything based on data from peers.

## Personal mode

`profile.activeView = 'personal'` (`PERSONAL_VIEW`, `core/src/lan.ts`; never a team tag — those are 11 chars) = this PC alone, offline. Chosen from the switcher's 🏠 tab (`setActiveView {view: 'personal'}`, privileged; any other unknown view is refused with officesState); public or a team tab switches back. Team memberships stay in profile.json (inactive), so switching back needs no code; `leaveOffice` keeps personal; create/join switch to the team. PeerNet `offline()` (cli.ts → `lan.personal`): `sendNow` sends nothing (no hello, no presence), `receive` drops everything (no hello reply), `peers()` is empty, `prune` clears all peer state; `LanService.office/people` also skip peers. The snapshot = this PC's agents + self. Chat works and stays local (`view: 'personal'`, never on a channel). Layout: own file `layout-personal.json` + bundled `default-layout-personal.json` (`AssetCache.personalLayout`); `saveLayout`/`layoutLoaded`/Reset (webview `PERSONAL_LAYOUT_ASSET`) follow the current mode. Switching personal on/off sends `layoutLoaded` before `officesState` (`onOfficesChanged(layoutChanged)`), and the webview refits the camera from the default zoom when the mode changes (App fit effect keyed by `isPersonal(offices)`). Two-instance check: `.superpowers/personal/e2e.mjs` (local only).

## Datagram size (split presence)

Every PeerNet datagram is ≤ `MAX_DATAGRAM_BYTES` (1200) on the wire: some networks (and WSL loopback) drop IP fragments, i.e. anything over 1472 B. `pub`/`team` presence whose datagram fits is sent in the old single form (the Inner `{seq, packet, office?}`, byte-identical to 0.4.x; one seq per send tick, shared by every pub peer). A larger one is deflated and split into ≤ 48 parts `{seq, from, part, parts, d}` (420 B each, inside the same seal/AAD); `fitPacket` trims trailing views until it fits. 0.4.x peers drop parts, so a busy PC is missing for them (documented in the install guides and README). The receiver keeps one assembly per (channel, sender), ≤ 256 in all, a newer seq replaces an unfinished one, unfinished ones expire after 2 s (the last complete state stays), the replay guard applies to complete seqs, and a complete one is inflated (≤ MAX_PACKET_BYTES) and must match the part header's seq and sender (pub: also the wire `from`).

## Data

`~/.pixel-office/` — `layout.json` (this PC's layout, shown in the public and every team office; `layout-personal.json` in personal mode; never sent to peers — sharing = export/import file), `config.json`, `profile.json` (0600: X25519 key pair, team office secrets, optional nickname + `nicknameSince` (set when it changes; migrated = file mtime), `setUp` = first-run form saved; `chat` = my current chat bubble + its view; the OS account name is NOT stored — `LanService.account` = `osAccount()` at every start, `DOMAIN\` stripped, ≤32, else hostname; never settable by a client), `known-peers.json` (0600, TOFU peer id → public key). Ports: UDP 47800 (peers; the only inbound port — Windows firewall rule `protocol=UDP localport=47800`), HTTP 47801 (UI, this PC only); the CLI defaults to `--host 127.0.0.1 --port 47801` (`--host` is kept for dev; non-loopback requests are refused anyway). A UDP bind failure only disables peers. Two instances on one host (tests only): `PIXEL_OFFICE_UDP_PORT=47810 PIXEL_OFFICE_UDP_TARGETS=127.0.0.1:47811` and the mirror for the other.

## Conventions

- **Protocol**: edit `core/asyncapi.yaml`, run `npm run asyncapi:generate`; CI fails if `core/src/messages.ts` drifts. Every message sets `additionalProperties: false`.
- **Constants**: no inline magic numbers/strings. Server → `server/src/constants.ts`; protocol → `core/src/constants.ts`; webview → `webview-ui/src/constants.ts`; CSS variables in `webview-ui/src/index.css` `:root`.
- **Colors**: hex/rgb/hsl literals only in `webview-ui/src/constants.ts` (eslint `pixel-agents/no-inline-colors`, error level). Pixel style: `borderRadius: 0`, `2px solid` borders, hard `2px 2px 0px` shadows. UI font Pretendard (`var(--font-ui)`, bundled `webview-ui/public/fonts/`, OFL; eslint `pixel-agents/ui-font`).
- **TypeScript**: no `enum` (use `as const`); `import type` for type-only imports; `.js` extensions on relative imports in `server/` and `core/`; `noUnusedLocals`/`noUnusedParameters` everywhere.
- **No new runtime dependencies** — UDP, file watching, paths via Node stdlib.
- **User-facing text via `webview-ui/src/i18n.ts`** (`t(key, params?)`, ko/en per viewer, `localStorage['pixel-office.lang']`, default from `navigator.language`). Agent activity travels as `{act, target}` and is rendered by each viewer; `reason`/targets are shown as-is. Layout room labels stay 코딩실, 자료실, 서버실, 대기실 (keys coding|library|server|lounge) and are translated only for display (`areaName`).
- Logging: `console.*` with `[Pixel Office]` (server) / `[Webview]` prefixes.
- Keep the upstream MIT LICENSE and the JIK-A-4 Metro City character credit.
- Commits: husky pre-commit runs gitleaks + lint-staged; never `--no-verify`.

## Office UI essentials

- Game state lives in the imperative `OfficeState` (not React). Zoom is a float (0.25–10, wheel = `wheelZoom`; first open fits the office below a `FIT_TOP_MARGIN_PX` band so the switcher never covers the room names); the frame is drawn at the integer `renderScale(zoom).renderZoom` (sprite caches stay per-integer) and blitted scaled — below zoom 1 only the visible map is rendered and the background is painted on screen; overlays/hit-tests use `mapOffset`/`overlayProjection` with the float zoom. No `ctx.scale(dpr)`, z-sort by Y. Floor/wall-base/carpets are cached in LRU chunks (~512 device px, `FLOOR_CACHE_MAX_PIXELS`; an edit drops only the chunks it touched, `office/engine/floorChunks.ts`); wall instances and room-name positions are cached per layout; off-screen furniture is culled. The canvas effect never re-runs per edit (a canvas width/height assignment clears it: only on a real resize).
- Layout model `{ version: 1, cols, rows, tiles, furniture, tileColors?, areas?, areaTiles?, background? }` (`background` = map fill outside the office/VOID tiles, `office/background.ts`; missing = page navy); grid ≤ 128×128 (`MAX_LAYOUT_COLS/ROWS`, `core/src/lan.ts`); the bundled default (`scripts/generate-lan-layout.mjs` → `default-layout-1.json`, deterministic) is 90×60 (코딩실 75 / 자료실 60 / 서버실 64 / 대기실 144 seats); `--personal` → `default-layout-personal.json`, 34×22, 8 seats per room (same rooms/corridor, per-variant furniture counts in the script's `V`; `test/lanLayout.test.ts` checks both match the generator) and the size is fixed (no grid expansion in the editor; an imported/older layout of another size is shown as is; Settings → reset to the default office); saved via `saveLayout` from the editor (loopback only).
- Rooms are fixed: `areas` = exactly 코딩실/자료실/서버실/대기실 (`normalizeRoomAreas` in `core/src/lan.ts`: missing rooms added with default colors, unknown areas and their tiles dropped). Applied by the webview on `layoutLoaded`/import (`migrateLayout`) and by the server on save and load (`sanitizeLayout`, `server/src/layoutPersistence.ts`, which strips legacy `pets`). Room tiles come only from the default layout: a room without tiles takes the default's tiles when the grid is the default size (`fillMissingRooms`, server sanitize + webview import). Grid check shared by the server, the import and `layoutLoaded`: `isLayoutGrid` (v1, cols/rows ≤ 128, `tiles.length === cols*rows`, furniture array); a written `saveLayout` answers `layoutSaved` to the sender (the editor's [Save] leaves edit mode only on it, `office/editor/saveFlow.ts`; no answer in 5 s → error toast), a refused or unwritable one `layoutSaveRejected` (toast). A missing room color falls back to `ROOM_DEFAULT_COLORS`. There is no area tool; a room with no walkable tile is warned about in the editor.
- Layout editor: floor/wall/erase/furniture/background tools, 50-level stroke-scoped undo, Esc unwinds in stages; pure ops in `office/editor/editorActions.ts`. Undo/Redo/Save/Reset (`EditActionBar`) sit right of the bottom-left toolbar while editing.
- Characters never wander: a seated character stays seated (still when idle), a seatless one stands still; walking only happens between rooms or when following a leader (`updateCharacter`). Every character (main, subagent, shell) is placed by its own state/room; a child in the same room as its parent holds its hand (`setFollowTarget`), one in another room acts on its own (no ghost parents). Room name plates are DOM badges (`lan/RoomPlates.tsx`, pixel-panel, fixed font) just inside each room's top-left tile (first tile of the area in reading order), placed through `overlayProjection` and recomputed on `onFrame` (re-rendered only when a plate moved or its text changed); live counts `코딩실 5 · +3` (main agents by their own room, +N = children; `roomCounts`/`plateText`, `OfficeState.roomCounts`). Hidden while Show Areas draws the area labels on the canvas.
- On-demand rendering (`office/engine/gameLoop.ts`): a frame runs only after `requestRender(reason)` or when `OfficeState.nextFrameIn(nowSec)` says the scene animates — 0 = every rAF (walk, matrix effect, IDLE about to path, camera glide), N s = one timer wake at the next boundary (typing frame, pet idle frame, follow retry, animated furniture), Infinity = asleep. Requests come from: any window input event (OfficeCanvas), every server message, `LanAgents.reconcile` (snapshots/demos), `highlightPeer`, `selectedAgentId`, `rebuildFromLayout`, resize, fonts, `subscribeTheme`, tour steps, and an App-level effect after every App render (safety net). New state the canvas or overlays show that changes outside these paths MUST call `requestRender`; a new self-animating thing MUST be reflected in `nextFrameIn`. `LanOverlay` re-renders via `onFrame` (skipped on pure timer wakes); TourOverlay keeps its own rAF while the tour runs. Tests: `test/renderScheduler.test.ts`; perf scripts in `.superpowers/perf/`.
- Chat (`lan/ChatLayer.tsx`, pure `lan/chat.ts`): `/` (no text field focused, not editing/touring/read-only/touch) opens an input at the mouse pointer (`pointerTile` = `overlayProjection.toWorldX/Y` / TILE_SIZE, clamped to the grid) — only when I am in the viewed office's snapshot (`people` has `self`); Enter sends `sendChat {text, col, row}` (privileged), Esc/blur cancels (my bubble stays), ≤ `CHAT_MAX_CHARS` (100) code points, 1 per `CHAT_MIN_INTERVAL_MS` (2 s) in the webview and the server. One bubble per PC, no expiry: `LanService.sendChat` replaces `profile.chat {id, text, ts, col, row, view}` (persisted in profile.json; dropped on load if malformed or its view is not open, and by `update()` whenever its view stops being open — leaving the team, or joining one for a public chat); `deleteChat` (privileged, the × on my own bubble) clears it; both answer the sender with a fresh `officeSnapshot` (no local echo). `chat {id, text, ts, col, row}` (`PeerPacket.chat`, `parseChat`: `cleanChatText`, finite coords clamped 0..127) goes only into that view's channel presence (`getPacket(channel)`); the snapshot's `people[].chat {id, text, col, row}` is each live person's current one (gone with the peer or its next chat-less presence; no receiver-side rate limit). The webview (`ChatBubbles.apply`) rebuilds the bubbles from every snapshot (server messages already `requestRender`), wraps text (`wrapLines`), stacks overlapping bubbles upward (`stackBubbles`) with a tail to the spot. Bubbles anchor to world tile coords (a spot outside this PC's grid sits at its edge). Two-instance Playwright check: `.superpowers/chat/e2e.mjs` (local only).
- Top right is one stack (no overlaps): update banner, install popup, people panel (takes the height left). Top left (`components/ZoomControls.tsx`): the dark/light toggle (`data-tour="theme-toggle"`, sets an explicit dark/light even when the pref is `system`; also on mobile), then + and − side by side (`data-tour="zoom"`, desktop only), then the room legend at `ROOM_LEGEND_TOP_PX` (`lan/RoomLegend.tsx`, collapsible, hidden while editing) with the name-tag toggle under it.
- Theme (per viewer, `src/theme.ts`, localStorage `pixel-office.theme`: dark default = the original look, light = near-white chrome and a lifted office, system): `<html data-theme>` re-points the CSS variables in `index.css` (`:root[data-theme='light']`); the canvas reads `getTheme()` every frame and maps floors/walls/furniture/background through `office/themeColors.ts` (pure per-pixel HSL transforms, `LIGHT_THEME_TRANSFORMS`, cached per sprite; floor chunks and wall instances keyed by theme; characters/pets never transformed). Never a CSS/canvas `filter` (pixel-crisp; `test/theme.test.ts` scans for it).
- Assets: per-furniture `manifest.json` under `webview-ui/public/assets/furniture/`, characters `char_0..5.png`, floors, walls, carpets, pets.
